# یادداشت انتشار — نسخه ۳.۲.۲ «ورود مطمئن + طراحی تازهٔ صفحه ورود»

تاریخ انتشار: ۱۴۰۴/۹/۲ (۲۰۲۶-۱۱-۲۳)

## 🐞 رفع باگ بحرانی: ورود با «no such table: users» شکست می‌خورد

علامت (لاگ کاربر): صفحه وب باز می‌شد اما با هر حساب نمونه، خطای ۵۰۰ و در کنسول:

```
sqlite3.OperationalError: no such table: users
[i] دیتابیس جدید ساخته می‌شود.
```

ریشه: در بستهٔ CI هیچ دیتابیس بذرشده‌ای نبود (`backend/education.db` فایلی
گیت‌پذیر نیست و هنگام build وجود نداشت) و اپ هم برای دیتابیس SQLite خالی هیچ
بوت‌استرپی نداشت — جدول‌ها هیچ‌وقت ساخته نمی‌شدند. (جالب: smoke-test قدیمی CI
این را هم نمی‌دید چون خودش میراث v2.x بود و فقط هشدار می‌داد.)

اصلاحات دو لایه:

1. **بوت‌استرپ خودکار داخل اپ** (`app/core/bootstrap.py`): در startup، اگر
   دیتابیس SQLite خالی باشد (جدول users نیست)، کل schema با `create_all`
   ساخته می‌شود و سپس دادهٔ نمونهٔ دمو با همان **خط تولید واقعی** ریخته
   می‌شود (سرفصل → مفاهیم → محتوا → سؤال → آزمون → تسلط → برنامه مطالعه →
   استاد هوشمند). در Production (PostgreSQL) و دیتابیس‌های مقداردهی‌شده هیچ
   دخالتی نمی‌کند. کنترل با `S360_BOOTSTRAP_DEMO_SEED` (در تست‌ها خاموش).
2. **دیتابیس بذرشده وارد بستهٔ CI شد**: گام جدید «Seed demo database» قبل از
   PyInstaller یک `education.db` کامل می‌سازد و spec آن را در `_internal/`
   باندل می‌کند؛ لانچر در اولین اجرا آن را کنار exe کپی می‌کند.

نتیجه: ورود با `student.sara` / `prof.rezaei` / `edu.admin` (رمز همه
`Pass1234!`) از همان اولین اجرا کار می‌کند — چه با دیتابیس باندل‌شده چه با
دیتابیس خالی که خودکار بذر می‌شود.

## 🎨 بازطراحی کامل صفحه ورود — «Aurora Glass ۲۰۲۶»

- **پنل معرفی** با لوگوی گرادیانی، تیتر گرادیان، چهار ویژگی اصلی با آیکون‌های
  SVG داخل کاشی گرادیان (جای چیپ‌های ایموجی قدیمی)، و ردیف آمار.
- **حلقه aurora چرخان** پشت کارت + بافت نقطه‌ای + شفق — عمق و حرکت امروزی.
- **کارت شیشه‌ای** با حاشیه گرادیان متحرک، تب‌های pill، فیلدهای آیکون‌دار،
  **نمایش/پنهان‌کردن رمز**، دکمه گرادیان با اسپینر.
- **چیپ‌های «ورود سریع»**: کلیک روی هر حساب نمونه، فرم را خودکار پر می‌کند —
  دیگر چیزی برای اشتباه تایپ‌کردن باقی نمی‌ماند.
- کاملاً واکنش‌گرا: در موبایل فرم اول می‌آید و معرفی زیر آن؛ احترام به
  `prefers-reduced-motion`.
- منطق قبلی (ثبت‌نام، گردش‌کار تایید، SSO، پیام‌های خطا) یک حرف هم تغییر نکرده.

## 🧪 کیفیت و اثبات

- **۱۳۹ تست سبز** (۴ تست جدید بوت‌استرپ: ساخت schema روی db خالی، دست‌نزدن به
  db موجود، فراخوانی seed با مجوز، بی‌عملی برای غیر-SQLite).
- **شبیه‌سازی دقیق سناریوی کاربر**: دیتابیس کاملاً خالی → سرور بالا آمد →
  bootstrap کل خط تولید دمو را ساخت → ورود student.sara و prof.rezaei با ۲۰۰.
- **تست مرورگر واقعی** (headless): کلیک چیپ سارا → ورود → داشبورد با درس
  MATH101؛ اسکرین‌شات دسکتاپ ۱۴۴۰px و موبایل ۳۹۰px بدون سرریز افقی.
- **smoke-test CI جدید با شکست سخت**: healthz + serve UI + **ورود واقعی با
  حساب نمونه** + سرویس‌دهی — اگر ورود در exe کار نکند، build قرمز می‌شود (قبلاً
  این چک فقط هشدار می‌داد و میراث v2.x بود).
